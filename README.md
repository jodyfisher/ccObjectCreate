# ccObjectCreate

A C generator for database objects and supporting C#/form snippets. It reads a
semicolon-separated field definition file and writes files in the current directory.

## Build and run

```bash
gcc -Wall -Wextra -o ccObjMaker ccObjMaker.c
./ccObjMaker Sample fields.csv
```

Rebuild after pulling source changes. The historical `ccObjMaker` executable in
this repository is not regenerated by this repair; use the command above to obtain
an executable for your own platform.

Each input line has these columns, without a header:

```text
fieldName;SQL type;extra SQL definition;editor kind;lookup table
```

The last two columns may be omitted. Editor kind defaults to `0`; the current
generator does not use editor-kind or lookup-table values to build controls.
For example:

```text
Quantity;INT;NOT NULL DEFAULT 0;0;
Amount;DECIMAL(12,3);NOT NULL DEFAULT 0;0;
Description;VARCHAR(100);NOT NULL DEFAULT '';0;
```

Blank lines and surrounding whitespace are accepted, as are LF/CRLF and a missing
final newline. Names must be simple identifiers, with no spaces or punctuation.
C# reserved keywords are rejected. Use names suitable for SQL as well; SQL keywords
are not escaped by this generator.
Do not include the primary key or standard audit/lock columns: they are generated.
Limits are 128 fields and 127 characters per input column. Semicolons delimit
columns; quoted/escaped semicolons inside values are not supported.

The model mapping follows the existing convention: integer types become `int`,
DECIMAL/NUMERIC/FLOAT/DOUBLE/REAL become `double`, date/timestamp types become
`DateTime`, and text/encrypted VARBINARY values become `string`. TIME retains the
legacy DateTime representation; adapt that mapping/reader for applications using
TimeSpan. Nullable SQL fields retain the existing model's default-value mapping;
this repair does not introduce nullable BO properties. Other SQL types require
review rather than assuming a complete MySQL/SQL Server type mapper.

## Use the output

- `<Object>.mysql` and `<Object>.sql` are the MySQL and SQL Server definitions.
- `<Object>.cs` is a bundle containing BO, MySQL D, BL, audit-controller member
  output and an alternative SQL Server D implementation. Copy the relevant sections
  into their normal projects and supply imports/namespaces. Choose one D provider;
  compiling the complete bundle would duplicate that class. Merge the audit overload
  into the existing AuditLogController (the standalone partial wrapper marks its scope).
- `<Object>.frm.cs` contains snippets for an editor and a register form. Separate
  those sections: each has a constructor. Supply designer controls, binding sources,
  actual view/security identifiers, imports and the application-specific helpers.
  The final DataTable-save helper is a mapping example to integrate with the owning
  screen's save/history workflow, not a complete register persistence implementation.
- `<Object>.unit.cs` remains a test scaffold to adapt. Do not execute its database
  operations until its target, IDs and expectations have been configured.
- `<Object>.h` is the C++ model header.

The repair fixes input bounds, emitted C# syntax, helper call signatures, numeric
entry conversion, floating-value reads, encrypted sort branches and key forwarding,
SQL projection separators, filter accumulation and MySQL procedure delimiters.
It preserves the existing caller-managed audit approach; it does not retrofit the
newer AAFD object-template save/history contracts or provide transactional saves.
Generated SQL and encryption-helper contracts still need review against the target
application and database before deployment. MySQL encrypted reads require a
connection configuration permitting the connection-local `@key` variable.

## Regression checks

No checks connect to a database. GCC, G++ and Python 3 are required:

```bash
python3 tests/test_generator.py
python3 tests/test_generator.py --sanitize
```

The sanitizer option enables address/undefined-behaviour checks. On a host where
LeakSanitizer cannot inspect processes (for example under ptrace), run with
`ASAN_OPTIONS=detect_leaks=0`; this disables leak checking only.

For stronger C# checks, build the optional tool with a .NET 8-compatible SDK:

```bash
dotnet build tests/CSharpChecks/CSharpChecks.csproj -c Release
python3 tests/test_generator.py --csharp-checker 'dotnet tests/CSharpChecks/bin/Release/net8.0/CSharpChecks.dll'
```

That tool compiles both provider alternatives with test stubs and checks form
snippet syntax. It does not validate real provider behaviour, application helper
compatibility, designer controls or execution of database procedures.
